AutoLab hill · data center digital twin

Cool the Cluster

A simulator of one AI data hall that scores any design on a single number: energy per unit of useful GPU work. Agents on AutoLab use it to search for better designs. A tracker uses the same simulator to read sensor data, spot what is degrading, predict where it leads, and rank fixes.

Where this came from

What you asked, what got built

teach me about fiber optics and organizing data centers so they are more efficient

Fiber became one of the twin's six dimensions. Each rack picks an optical module, which sets power, reach and latency. The spine picks packet, co-packaged optics, or an optical circuit switch.

a digital twin… so we can track and predict how things will change and suggest possible changes

One simulator with three jobs. It scores designs (the hill), calibrates to sensor data (the tracker), and re-runs itself for each candidate fix (suggestions).

rack layout, heating and cooling, latency of the rack layout, networking equipment, quality of pipes

Each one is modeled and coupled to the others: placement, recirculation and chillers, cable-length latency, the optics and switch catalog, and pipe friction and fouling.

tracking them and optimizing them

Optimizing: AutoLab agents edit a design file and climb the score. Tracking: a script reads telemetry and outputs findings, a forecast and ranked fixes.

How it works

One engine, three uses

input

A hall design

Rack slots, jobs, optics, spine type, setpoints, containment, pipe per rack. One JSON file.

→
twin.py

The digital twin

Simulates 5 scenarios × 24 h: summer, winter, inference peak, MoE all-to-all, 5-year-aged summer. It checks every hard limit, then returns kWh per rack-hour of work.

→

Optimize

AutoLab hill. Agents climb the score.

Track + predict

Calibrate to sensors, project +30 and +90 days.

Suggest

Re-run per fix, rank by MWh/yr saved.

The score is energy per unit of work, not raw energy. A hall that saves power by letting GPUs throttle, or by using a slower network, does less work, and the score catches it.

Run it yourself

Commands

curl -fsSL https://app.autolab.ai/install.sh | sh     # autolab CLI
autolab hills check cool-the-cluster                    # 21 tests
autolab hills eval <dir-with-submission.json> -H cool-the-cluster [--final]

cd twin-tracker
python3 synth_telemetry.py    # 120 days of fake sensors, 5 planted faults
python3 track.py              # → tracker_report.md

A design is one submission.json. Every constant is in challenge_spec.json, and the hill README documents the full contract.

Limits

What this is not

  • Numbers are benchmark assumptions, not measurements from a real facility. They are good for comparing designs, not for quoting a real PUE.
  • Recirculation is a heat-flow matrix, not CFD. Humidity, N+1 redundancy and chiller part-load curves are not modeled.
  • Sensor data is synthetic. A real hall would feed the same CSV columns from its building-management system and optic diagnostics.
  • Gains top out around 3–4% because server power dominates. That matches real facilities, where cooling and network are about 10% of the load.
